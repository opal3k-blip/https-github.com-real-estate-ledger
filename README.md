# دفتر الفرص العقارية — نسخة سحابية (GitHub + Firebase)

أداة تقييم وتحليل جدوى الفرص الاستثمارية العقارية — نسخة مستقلة تعمل على رابط ثابت خاص بك،
مع قاعدة بيانات سحابية حقيقية (Firebase Firestore) تتيح لك ولزملائك فتح نفس البيانات من أي
جهاز، وتصدير Excel/PowerPoint والطباعة كـ PDF بدون أي قيود (هذه القيود كانت خاصة فقط بمعاينة
المحادثة داخل Claude — هنا لا توجد).

هذا الدليل مكتوب بافتراض أنك **لا تملكين خبرة برمجية سابقة** — كل خطوة موضّحة بالتفصيل.

---

## نظرة عامة على الملفات

| الملف | الوظيفة |
|---|---|
| `index.html` | التطبيق كاملاً (الواجهة + محرك الحسابات + الربط بقاعدة البيانات) — ملف واحد فقط |
| `firebase-config.js` | مفاتيح الاتصال بمشروع Firebase الخاص بك (تعدّلينها مرة واحدة) |
| `README.md` | هذا الدليل |

---

## الخطوة ١: إنشاء مشروع Firebase (قاعدة البيانات السحابية)

1. افتحي [console.firebase.google.com](https://console.firebase.google.com) وسجّلي دخول بحساب Google.
2. اضغطي **Add project / إضافة مشروع**. اختاري اسماً (مثلاً `real-estate-ledger`)، واستمري بالإعدادات الافتراضية (يمكنك إيقاف Google Analytics — غير ضروري هنا).
3. بعد إنشاء المشروع، من القائمة الجانبية اختاري **Build → Firestore Database**.
4. اضغطي **Create database**.
   - اختاري موقع الخادم الأقرب لك (مثلاً `eur3` أو `me-central1` إن كان متاحاً لمنطقة الشرق الأوسط).
   - عند سؤالك عن وضع القواعد الأمنية، اختاري **Start in test mode** مبدئياً (سنضبطها يدوياً في الخطوة ٣).

## الخطوة ٢: ربط التطبيق بمشروعك (نسخ مفاتيح الإعداد)

1. من صفحة المشروع الرئيسية في Firebase Console، اضغطي أيقونة الترس ⚙️ بجانب "Project Overview" ثم **Project settings**.
2. انزلي لقسم **Your apps**، واضغطي أيقونة الويب `</>`.
3. أدخلي اسماً للتطبيق (مثلاً `reop-web`) واضغطي **Register app**. **لا تحتاجين** لتفعيل Firebase Hosting هنا (سننشر عبر GitHub Pages بدلاً منه).
4. ستظهر لك قطعة كود فيها كائن `firebaseConfig` يشبه هذا:
   ```js
   const firebaseConfig = {
     apiKey: "AIzaSy...",
     authDomain: "real-estate-ledger.firebaseapp.com",
     projectId: "real-estate-ledger",
     storageBucket: "real-estate-ledger.appspot.com",
     messagingSenderId: "123456789",
     appId: "1:123456789:web:abcdef123456",
   };
   ```
5. افتحي ملف `firebase-config.js` في هذا المجلد، واستبدلي كل قيمة `"REPLACE_ME"` بالقيمة المقابلة من الكائن أعلاه. **احفظي الملف**.

## الخطوة ٣: ضبط قواعد الأمان (Security Rules)

بشكل افتراضي (test mode)، قاعدة البيانات مفتوحة للقراءة والكتابة لأي شخص يعرف الرابط لمدة ٣٠ يوماً فقط ثم تُغلق تلقائياً. لجعلها تعمل بشكل دائم:

1. في Firebase Console، افتحي **Firestore Database → Rules**.
2. استبدلي المحتوى بالتالي:
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /opportunities/{oppId} {
         allow read, write: if true;
       }
     }
   }
   ```
3. اضغطي **Publish**.

> ⚠️ **تنبيه مهم**: القاعدة أعلاه تسمح لأي شخص يملك رابط الموقع بقراءة وتعديل كل الفرص. هذا مقبول
> طالما الرابط لا يُشارك إلا مع فريقك مباشرة (وليس منشوراً علناً). إذا أردتِ لاحقاً تقييد الدخول
> بحساب/كلمة مرور (Firebase Authentication)، أخبريني وأضيفه — يحتاج تعديلاً إضافياً بسيطاً على
> الكود وليس فقط القواعد.

## الخطوة ٤: رفع الكود إلى GitHub

بما أن لديك حساب GitHub بالفعل:

1. اذهبي إلى [github.com/new](https://github.com/new) وأنشئي مستودعاً جديداً (Repository):
   - الاسم: مثلاً `real-estate-ledger`
   - اختاري **Public** (مطلوب لتفعيل GitHub Pages مجاناً) أو Private إذا كان لديك خطة تدعم Pages للمستودعات الخاصة.
   - **لا** تُفعّلي "Add a README file" (لدينا واحد جاهز).
2. بعد إنشاء المستودع، ستظهر لك صفحة فيها أوامر جاهزة تحت عنوان
   "…or push an existing repository from the command line". افتحي الطرفية (Terminal على
   Mac/Linux، أو Git Bash على Windows) داخل هذا المجلد (الذي يحوي `index.html`) ونفّذي:
   ```bash
   git init
   git add .
   git commit -m "النسخة السحابية الأولى — دفتر الفرص العقارية"
   git branch -M main
   git remote add origin https://github.com/USERNAME/real-estate-ledger.git
   git push -u origin main
   ```
   (استبدلي `USERNAME` باسم المستخدم الخاص بك، وسيطلب منك تسجيل الدخول أول مرة).

## الخطوة ٥: تفعيل GitHub Pages (النشر المجاني)

1. داخل صفحة المستودع على GitHub، اذهبي إلى **Settings → Pages**.
2. تحت **Build and deployment → Source**، اختاري **Deploy from a branch**.
3. تحت **Branch**، اختاري `main` والمجلد `/ (root)`، ثم اضغطي **Save**.
4. انتظري دقيقة أو دقيقتين، ثم أعيدي فتح نفس الصفحة (Settings → Pages) — سيظهر رابط مثل:
   `https://USERNAME.github.io/real-estate-ledger/`
5. افتحي هذا الرابط — هذا هو موقعك الدائم. جربي:
   - إضافة فرصة جديدة، ثم فتحها من جهاز آخر (أو متصفح آخر) للتأكد أن البيانات تظهر (يعني قاعدة البيانات السحابية شغّالة).
   - زر "طباعة / PDF" — يجب أن يفتح نافذة الطباعة العادية للمتصفح.
   - زري "Excel" و"PowerPoint" — يجب أن يبدأ التحميل مباشرة بدون أي رسالة خطأ.

## تحديث الموقع لاحقاً

أي تعديل تريدين إضافته على `index.html` مستقبلاً: عدّلي الملف محلياً، ثم:
```bash
git add .
git commit -m "وصف التعديل"
git push
```
سينشر GitHub Pages النسخة الجديدة تلقائياً خلال دقيقة أو دقيقتين.

## أسئلة شائعة

**هل بيانات الفرص تُشارك بين كل من يفتح الرابط؟**
نعم — كل من يفتح الرابط يرى نفس قاعدة البيانات ويقدر يضيف/يعدّل عليها (حسب قواعد الأمان في
الخطوة ٣). هذا مقصود لتشارك الفريق نفس الفرص.

**هل هذا مجاني؟**
نعم — GitHub Pages مجاني بالكامل، وFirebase Firestore له باقة مجانية سخية (Spark Plan) كافية
جداً لعدد فرص محدود (عشرات الآلاف من العمليات يومياً مجاناً) — لن تحتاجي للترقية إلا لو استخدم
الأداة عدد كبير جداً من الأشخاص يومياً.

**فقدت التصدير أو الطباعة تعمل من قبل بشكل جزئي داخل محادثة Claude — ليه هنا هتشتغل بشكل كامل؟**
لأن معاينة المحادثة (iframe) بها قيود أمان تمنع التحميل التلقائي للملفات ونافذة الطباعة. موقعك
هنا يعمل كصفحة ويب عادية مستقلة بدون أي قيود من هذا النوع.
