# دفتر الفرص العقارية — نسخة سحابية (GitHub + Firebase)

أداة تقييم وتحليل جدوى الفرص الاستثمارية العقارية — نسخة مستقلة تعمل على رابط ثابت خاص بك،
مع قاعدة بيانات سحابية حقيقية (Firebase Firestore) محمية بتسجيل دخول (Firebase Authentication)
تتيح لك ولزملائك فتح نفس البيانات من أي جهاز بعد تسجيل الدخول، وتصدير Excel/PowerPoint والطباعة
كـ PDF بدون أي قيود.

هذا الدليل مكتوب بافتراض أنك **لا تملكين خبرة برمجية سابقة** — كل خطوة موضّحة بالتفصيل.

## نظرة عامة على الملفات

| الملف | الوظيفة |
|---|---|
| `index.html` | التطبيق كاملاً (الواجهة + محرك الحسابات + تسجيل الدخول + الربط بقاعدة البيانات) — ملف واحد فقط |
| `firebase-config.js` | مفاتيح الاتصال بمشروع Firebase — **مُعبّأة بالفعل بمشروعك** `real-estate-ledger-f85a6` |

## ✅ ما تمّ إعداده تلقائياً بالفعل

- مشروع Firebase: `real-estate-ledger-f85a6` (Firestore مفعّل).
- تطبيق ويب مسجَّل باسم `reop-web`، ومفاتيحه منسوخة بالفعل في `firebase-config.js`.
- شاشة تسجيل دخول داخل `index.html` (بريد إلكتروني/كلمة مرور + "متابعة عبر Google") — **بدون تسجيل ذاتي**: الحسابات تُنشأ من قِبل مسؤول النظام فقط (إنتِ).
- **وصول مقيَّد بفريقك فقط، بمدة قابلة للتحديد**: قواعد أمان Firestore منشورة تشترط أن يكون بريد المستخدم إما بريدك (مسؤول دائم) أو مضافاً عبر لوحة "👥 إدارة الفريق" الظاهرة في أعلى التطبيق (تظهر فقط عندما تكوني مسجّلة دخول ببريدك `opal3k@gmail.com`). أي شخص غير مضاف، أو انتهت مدته، يرى شاشة "غير مصرَّح لك بالدخول" فوراً.
- لكل فرصة عقارية: اسم/بريد من أضافها وآخر من عدّلها يظهر في أعلى مذكرة التقييم.
- مؤشر "🟢 متصل الآن" في الشريط العلوي يعرض عدد وأسماء من فاتح الموقع فعلياً هذه اللحظة (يعتمد على نبضة كل ٢٥ ثانية من كل جهاز مفتوح).
- **لوحة قيادة محفظة موسّعة** (أعلى قائمة الفرص): ١٠ مؤشرات أداء (عدد الفرص، TPC، إجمالي الدين، إجمالي حقوق الملكية، متوسط Equity IRR/MOIC/DSCR/Yield on Cost، وتوزيع الأحكام الاستثمارية 🟢🟡🔴)، وخمسة رسوم بيانية (تركيبة المحفظة حسب النوع، توزيع الأحكام، حجم المحفظة حسب المدينة، مقارنة Equity IRR بين الفرص، وخط زمني لعدد الفرص المُضافة شهرياً)، مع **فلاتر** (حسب المدينة/نوع الفرصة) تُحدّث كل المؤشرات والرسوم لحظياً بدون التأثير على قائمة الفرص الكاملة أسفلها.
- **لوحة "الأداء مقابل المعايير المرجعية"**: تقارن متوسط Yield on Cost الفعلي لفرص الدخل التأجيري لديك (لكل نوع استخدام) بأرقام NIY المرجعية المُستخدَمة أثناء إدخال كل فرصة (نفس الجدول الداخلي `USE_TYPES`، وليست بيانات سوق حية) — عدّلي أرقام هذا الجدول داخل `index.html` كلما توفّرت لديك أرقام أحدث من تقارير سوق موثوقة (مثل تقارير CBRE أو JLL الفصلية) لتعكس اللوحة معايير سوق حقيقية.

### كيف تضيفي/تحذفي شخصاً من الفريق

1. سجّلي دخول ببريدك (`opal3k@gmail.com`) — هيظهرلك زر **👥 إدارة الفريق** في أعلى الصفحة.
2. اكتبي بريد الشخص، واختاري مدة الوصول (**أسبوع** / **شهر** / **3 أشهر** / **دائم**)، ثم **إضافة**.
3. لازم كمان تنشئي له حساب دخول فعلي: [Authentication → Users → Add user](https://console.firebase.google.com/project/real-estate-ledger-f85a6/authentication/users) بنفس البريد وكلمة مرور تحددينها إنتِ وتبعتيها له — أو لو بريده Gmail، يقدر يدخل مباشرة بزر "متابعة عبر Google" بدون ما تعمليله حساب بريد/كلمة مرور.
4. بعد انتهاء المدة، الشخص هيشوف "غير مصرَّح لك بالدخول" تلقائياً بدون أي تدخل منك — ولو حبيتي تشيليه قبل الميعاد، دوسي **إزالة** بجانب اسمه في نفس اللوحة في أي وقت.

## ⚠️ خطوتان يدويتان متبقيتان (مرة واحدة فقط)

Firebase لا يسمح بتفعيل "طرق تسجيل الدخول" أو إضافة نطاقات موثوقة إلا من داخل الكونسول مباشرة (لا توجد أداة سطر أوامر لهذا). لازم تعمليهم بنفسك:

### ١) تفعيل طرق تسجيل الدخول

1. افتحي [Authentication → Sign-in method](https://console.firebase.google.com/project/real-estate-ledger-f85a6/authentication/providers) لمشروعك.
2. دوسي **Email/Password** → فعّليه (Enable) → **Save**.
3. دوسي **Google** → فعّليه → اختاري بريد دعم (Support email) → **Save**.

### ٢) إضافة رابط GitHub Pages كنطاق موثوق (بعد نشر الموقع في الخطوة ٤ أدناه)

1. في نفس الصفحة، افتحي تبويب **Settings** (أو **Authentication → Settings → Authorized domains**).
2. دوسي **Add domain** وأضيفي رابط موقعك بدون `https://`، مثلاً:
   `USERNAME.github.io`
3. **Save**.

> بدون هذه الخطوة، سجيل الدخول عبر Google تحديداً هيفشل برسالة `auth/unauthorized-domain` (البريد/كلمة المرور بيشتغل بدونها).

## الخطوة ٣: رفع الكود إلى GitHub

1. اذهبي إلى [github.com/new](https://github.com/new) وأنشئي مستودعاً جديداً (Repository):
   - الاسم: مثلاً `real-estate-ledger` (اسم بسيط بدون مسافات أو رموز — لا تلصقي رابط كامل في هذه الخانة).
   - اختاري **Public** (مطلوب لتفعيل GitHub Pages مجاناً) أو Private إذا كان لديك خطة تدعم Pages للمستودعات الخاصة.
   - **لا** تُفعّلي "Add a README file" (لدينا واحد جاهز).
2. بعد إنشاء المستودع، ستظهر لك صفحة فيها أوامر جاهزة تحت عنوان
   "…or push an existing repository from the command line". افتحي الطرفية (Terminal على
   Mac/Linux، أو Git Bash على Windows) داخل هذا المجلد (الذي يحوي `index.html`) ونفّذي:
   ```bash
   git init
   git add .
   git commit -m "النسخة السحابية — دفتر الفرص العقارية مع تسجيل الدخول"
   git branch -M main
   git remote add origin https://github.com/USERNAME/real-estate-ledger.git
   git push -u origin main
   ```
   (استبدلي `USERNAME` باسم المستخدم الخاص بك، وسيطلب منك تسجيل الدخول أول مرة).

## الخطوة ٤: تفعيل GitHub Pages (النشر المجاني)

1. داخل صفحة المستودع على GitHub، اذهبي إلى **Settings → Pages**.
2. تحت **Build and deployment → Source**، لو ظاهرلك **GitHub Actions** غيّريها إلى **Deploy from a branch**.
3. تحت **Branch**، اختاري `main` والمجلد `/ (root)`، ثم اضغطي **Save**.
4. انتظري دقيقة أو دقيقتين، ثم أعيدي فتح نفس الصفحة (Settings → Pages) — سيظهر رابط مثل:
   `https://USERNAME.github.io/real-estate-ledger/`
5. **قبل ما تجربي تسجيل الدخول**: ارجعي لقسم "إضافة رابط GitHub Pages كنطاق موثوق" أعلاه وأضيفي `USERNAME.github.io`.
6. افتحي الرابط وجربي:
   - تسجيل الدخول ببريدك (`opal3k@gmail.com`) — عبر Google أو عبر بريد/كلمة مرور تنشئيها لنفسك من [Authentication → Users](https://console.firebase.google.com/project/real-estate-ledger-f85a6/authentication/users).
   - إضافة فرصة جديدة، والتأكد إن اسمك ظهر كـ"أضافها" في تفاصيل الفرصة.
   - زر "طباعة / PDF" — يجب أن يفتح نافذة الطباعة العادية للمتصفح.
   - زري "Excel" و"PowerPoint" — يجب أن يبدأ التحميل مباشرة بدون أي رسالة خطأ.
   - إضافة بريد تجريبي من لوحة "إدارة الفريق"، وفتح الرابط من متصفح تاني (أو وضع تصفح خفي) بنفس البريد للتأكد إنه بيقدر يدخل ويشوف البيانات.

## تحديث الموقع لاحقاً

أي تعديل تريدين إضافته على `index.html` مستقبلاً: عدّلي الملف محلياً، ثم:
```bash
git add .
git commit -m "وصف التعديل"
git push
```
سينشر GitHub Pages النسخة الجديدة تلقائياً خلال دقيقة أو دقيقتين.

## أسئلة شائعة

**هل أي حد يقدر يعمل حساب ويشوف بياناتنا؟**
لأ. حتى لو حد سجّل دخول بحسابه في Google، مش هيقدر يشوف أو يعدّل أي بيانات إلا لو بريده مضاف
مسبقاً من لوحة "إدارة الفريق" (أو هو بريدك إنتِ). أي حد تاني بيشوف شاشة "غير مصرَّح لك بالدخول" فوراً.

**هل بيانات الفرص تُشارك بين كل أعضاء الفريق المصرَّح لهم؟**
نعم — كل عضو فريق مضاف (وفي مدة وصوله) يرى نفس قاعدة البيانات ويقدر يضيف/يعدّل عليها. هذا مقصود لتشارك الفريق نفس الفرص.

**ممكن أشوف مين فاتح الموقع دلوقتي؟**
نعم — مؤشر "🟢 متصل الآن" في أعلى الصفحة يعرض عدد وأسماء كل من فاتح الموقع خلال آخر ١.٥ دقيقة (مرري
الماوس فوقه لرؤية الأسماء)، وكل فرصة بتوضّح مين أضافها وآخر واحد عدّلها.

**هل هذا مجاني؟**
نعم — GitHub Pages مجاني بالكامل، وFirebase (Firestore + Authentication) له باقة مجانية سخية
(Spark Plan) كافية جداً لعدد فرص ومستخدمين محدود — لن تحتاجي للترقية إلا لو استخدم الأداة عدد
كبير جداً من الأشخاص يومياً.

**فقدت التصدير أو الطباعة تعمل من قبل بشكل جزئي داخل محادثة Claude — ليه هنا هتشتغل بشكل كامل؟**
لأن معاينة المحادثة (iframe) بها قيود أمان تمنع التحميل التلقائي للملفات ونافذة الطباعة. موقعك
هنا يعمل كصفحة ويب عادية مستقلة بدون أي قيود من هذا النوع.
