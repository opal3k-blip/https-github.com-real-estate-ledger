# سجل التدقيق غير القابل للتلاعب — Cloud Function

هذا المجلد يحتوي دالة سحابية واحدة (`mirrorOpportunityAuditLog`) تكتب سجل تدقيق حقيقي وغير قابل للتلاعب في مجموعة `oppAuditLog`، بديلاً عن الكتابة السابقة من العميل مباشرة.

## لماذا هذه الدالة ضرورية

قبل هذه المرحلة، كانت قواعد Firestore (`firestore.rules`) تسمح لأي عميل مصرَّح له بالكتابة المباشرة على `oppAuditLog`. هذا يعني أن "سجل التدقيق" كان يكتبه نفس الطرف الذي يُفترض أن يُراقَب — لا قيمة إثباتية حقيقية لسجل يستطيع الفاعل نفسه كتابته أو تعديله.

القاعدة الآن:

```
match /oppAuditLog/{id} {
  allow read: if isAuthorized();
  allow write: if false;   // لا كتابة عميل نهائياً — ولا حتى الأدمن
}
```

الكتابة الوحيدة الممكنة هي من هذه الدالة، التي تعمل بصلاحيات **Admin SDK** — تتجاوز Security Rules بتصميم Firebase نفسه. هذا هو "الخادم الموثوق" في السلسلة:

```
User → Application → Server Function → Immutable Audit Event
```

الدالة مُفعَّلة عبر `onDocumentWritten('opportunities/{oppId}')` — أي تعديل، إنشاء، أو حذف على أي وثيقة فرصة يُنتج تلقائياً سجل تدقيق مقابل، بصرف النظر عن الطريق الذي وصل عبره التعديل (الواجهة، سكربت مستقبلي، استيراد بيانات).

## متطلبات النشر (يجب أن تقوم بها أنت بنفسك)

**لا يمكن لـ Claude نشر هذه الدالة نيابةً عنك** — لا صلاحية وصول لحساب Firebase الحقيقي لديك من هذه البيئة. الكود مكتمل ومُختبَر بنيوياً (`node --check`، واختبار مباشر لمنطق `deepDiff`/`fieldLabel` عبر `_internal`)، لكن النشر الفعلي خطوات يجب تنفيذها من جهازك:

1. **خطة Blaze إلزامية.** Cloud Functions من الجيل الثاني (v2 — `onDocumentWritten`) لا تعمل على خطة Spark المجانية. من Firebase Console: Settings → Usage and billing → ترقية إلى Blaze. التكلفة المتوقعة لصندوق عقاري بحجم استخدام معتاد (عشرات-مئات الفرص، تعديلات يومية محدودة) ضئيلة جداً — عادة ضِمن الحد المجاني لخطة Blaze نفسه (أول ٢ مليون استدعاء شهرياً، ٤٠٠ ألف GB-ثانية).

2. **Firebase CLI:**
   ```bash
   npm install -g firebase-tools   # لو غير مُثبَّتة
   firebase login
   firebase use real-estate-ledger-f85a6   # أو معرّف مشروعك الفعلي من .firebaserc
   ```

3. **تثبيت الاعتماديات ثم النشر** (من جذر المستودع):
   ```bash
   cd functions
   npm install
   cd ..
   firebase deploy --only functions
   ```
   (أو `firebase deploy --only firestore:rules,functions` لنشر قواعد Firestore الجديدة والدالة معاً في أمر واحد — **يجب** نشر القواعد الجديدة قبل أو مع الدالة، وإلا سيستمر العميل بالمحاولة الفاشلة للكتابة على `oppAuditLog` بالقاعدة القديمة المخزَّنة سابقاً.)

4. **تحقّق من النشر:** من Firebase Console → Functions، يجب أن تظهر `mirrorOpportunityAuditLog` بحالة "Deployed". أول تعديل حقيقي على أي فرصة بعد النشر يجب أن يُنتج مستنداً جديداً في مجموعة `oppAuditLog` (يمكن مراقبته من Firestore Console مباشرة، أو من قسم "سجل التعديلات" في شاشة تفاصيل أي فرصة داخل التطبيق نفسه).

## ملاحظة تصميم مهمة: من أين تُقرأ هوية "من عدَّل"؟

الدالة تقرأ `meta.updatedBy`/`meta.createdBy` من وثيقة الفرصة نفسها لتحديد الفاعل. هذا الحقل محمي في `firestore.rules` بقاعدة `attributionHonest()` التي تفرض تطابقه دائماً مع بريد المستخدم المصادَق عليه فعلياً (`request.auth.token.email`) وقت الكتابة — فلا يمكن لعميل تزييف هوية "مَن غيَّر ماذا"، وهذا ما يجعل الاعتماد عليه من دالة خادم موثوقة آمناً ومنطقياً.

## ماذا لو لم تنشر هذه الدالة؟

التطبيق يستمر بالعمل بشكل طبيعي تماماً — لا يعتمد أي جزء آخر من النظام على هذه الدالة وظيفياً. الأثر الوحيد: قسم "سجل التعديلات" (Version History) في شاشة تفاصيل كل فرصة سيبقى **فارغاً لكل تعديل جديد** بعد نشر `firestore.rules` المحدَّثة (لأن الكتابة من العميل أصبحت مرفوضة بتصميم، ولا يوجد بديل يكتب محلّها بعد). في وضع الديمو/المحلي (`core.DEMO_MODE`) لا تتأثر تجربة السجل بأي حال — الكتابة المحلية هناك تعمل كما كانت دائماً (انظر التعليق في `src/features/audit-trail.js`).

## تزامن منطق الفرق (deepDiff) مع العميل

منطق `deepDiff`/`fieldLabel`/`FIELD_LABELS`/`IGNORE_PATHS` هنا **منقول يدوياً** من `src/features/audit-trail.js` (لا مستورَد — بيئتان منفصلتان تماماً: Node CommonJS هنا، ES module في متصفح العميل هناك، بلا أداة بناء مشتركة بينهما في هذا المشروع). أي تعديل مستقبلي على قواعد الفرق نفسها (حقول تُتجاهَل، طريقة مقارنة المصفوفات، تسميات حقول جديدة) **يجب تطبيقه في الملفين معاً** — وقد تُرك تعليق بالمثل في كل ملف يشير للآخر.
